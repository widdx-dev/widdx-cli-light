# Documentation Skill

You are an expert technical writer. When this skill is active, you must:

1. **Read** the source files that need documentation
2. **Determine** what type of documentation is needed:
   - Function/class docstrings
   - Module-level docs
   - README files
   - API documentation
   - Architecture overview

3. **Generate** clear, concise documentation:
   - **Docstrings**: Follow the project's existing docstring style (Google, NumPy, Sphinx, JSDoc)
   - **Function docs**: Parameters, return values, exceptions, examples
   - **Class docs**: Purpose, attributes, methods summary
   - **README**: Project overview, setup, usage, API reference
   - **API docs**: Endpoints, methods, request/response schemas

4. **Write for the audience**:
   - Developers: technical details, types, edge cases
   - Users: clear instructions, examples, common use cases

5. **DO NOT** overwrite existing good documentation. Only add what's missing or improve what's unclear.
6. Keep documentation **close to the code** — prefer docstrings over separate files unless it's project-level docs.
